## 任务四排错记录（ReAct 闭环）

**演练文件**：`index_buggy_demo.html`

- **报错证据**：点击「重置摆动」后控制台抛出
  `Uncaught ReferenceError: resetAnimation is not defined at HTMLButtonElement.onclick (index.html:68:15)`
- **Reflection 根因定位**：
  1. 按钮使用**内联属性** `onclick="resetAnimation()"`。内联 handler 的函数体只在**全局作用域**求值。
  2. 脚本中定义的函数名实为 `resetSimulationState()`，全局挂的是这个名字，**并不存在** `resetAnimation` 标识符。
  3. 两者名称不一致 → 点击时引擎去全局查找 `resetAnimation`，查无此标识符 → 抛出 `ReferenceError`。
  4. 报错**只在点击时出现**而非加载时，是因为内联属性值要等到事件触发才被求值。
- **修复**：
  1. 删除按钮的内联 `onclick` 属性；
  2. 函数统一重命名为 `resetAnimation()`；
  3. 改用 `addEventListener('click', resetAnimation)` 在脚本作用域内绑定（函数声明提升，绑定与点击时标识符均可见，同时规避 CSP 对内联脚本的限制）。
- **验收**：MS Edge headless 探针（自动 click + 错误监听 + 状态断言）→ `PASS`，`errCount=0`，点击后 `angle = π/4` 精准复位。

## 进阶挑战 A：双摆混沌模拟器

- **物理模型**：由单摆微分方程升级为**双摆拉格朗日动力学**，采用 **RK4 四阶数值积分**，固定步长 `1/480 s`。
  - $\ddot\theta_1 = \dfrac{-g(2m_1+m_2)\sin\theta_1 - m_2 g\sin(\theta_1-2\theta_2) - 2\sin(\theta_1-\theta_2)\,m_2(\omega_2^2 L_2 + \omega_1^2 L_1\cos(\theta_1-\theta_2))}{L_1(2m_1+m_2-m_2\cos 2(\theta_1-\theta_2))}$
  - $\ddot\theta_2 = \dfrac{2\sin(\theta_1-\theta_2)\big(\omega_1^2 L_1(m_1+m_2) + g(m_1+m_2)\cos\theta_1 + \omega_2^2 L_2 m_2\cos(\theta_1-\theta_2)\big)}{L_2(2m_1+m_2-m_2\cos 2(\theta_1-\theta_2))}$
  - **无发散保证**：分母 $D = 2m_1+m_2-m_2\cos 2(\theta_1-\theta_2) \in [2,4]$，永不为零，无数值奇点。
- **彩虹渐变衰减拖尾**：末端摆球轨迹以环形缓冲（220 点，移距 > 1.5 px 才记录）存储，逐段着色 `hsla(simTime·40 + frac·360, 90%, 62%, frac·0.85)`——色相随时间漂移，alpha 沿尾部衰减至 0。
- **拖拽交互**：`pointerdown` 在 36 px 内选取最近摆球；拖 bob1 时通过**逆运动学**反推 θ₂，使 bob2 屏幕位置保持拖拽瞬间不变（避免杆长视觉跳变）；释放时 ω₁=ω₂=0，物理从新位置重新演化。
- **验收**：4 s 仿真后 θ₁/θ₂/ω₁/ω₂/E 全部有限（`E = 11.813`）；拖 bob1 到 0.5 rad → 读数 29°（误差 0°）；拖 bob2 到 −0.4 rad → 读数 23°（误差 0°）；控制台 0 报错。

## 1. 意图清晰度反思

**问**：哪一次让 AI 编写代码时结果不符合预期？当时提示词缺少了哪一项要素（角色/目标/约束/验收标准）？后来如何补齐？

**答**：

不符合预期的是**任务四的排错环节**。我最初只提交了一张控制台报错截图和一句"点击重置按钮报错"的自然语言描述，AI 随即在无菌目录 `week05_pendulum_sim/index.html` 中反复检索 `resetAnimation`，结果为 **0 命中**，并据此给出"当前版本中该缺陷不存在、证据与代码不匹配"的结论——这与我眼前真实发生的现象直接矛盾，整轮交互被浪费。

回看当时的提示词，缺失的是**【约束（Boundary）】**这一项：我没有界定"**出错的文件究竟是哪一份**"。指导书给出的演练页路径是 `starter_code/03_buggy_practice/index.html`，而我实际把它放在了**仓库根目录** `人机协同实验/index.html`，与无菌工作区目录 `week05_pendulum_sim/` 处于并列位置。AI 按无菌隔离约定默认只在 `week05_pendulum_sim/` 内检索，自然一无所获。此外我的【报错证据】也只给了截图，没有附可检索的原始堆栈文本。

**补齐方式**：我用 `@` 把确切的文件路径附给 AI，并补上完整报错堆栈
`Uncaught ReferenceError: resetAnimation is not defined at HTMLButtonElement.onclick`。
信息补全后 AI 立刻定位到真正根因——按钮内联 `onclick="resetAnimation()"` 调用的函数，与脚本中实际定义的 `resetSimulationState()` **名称不一致**；内联 handler 只在全局作用域求值，因此点击瞬间才抛错。修复后点击可精准复位到 45°。

**教训**：四段式中【约束】不仅指技术边界，也包括**作用域边界**——必须指明"改哪个文件、在哪个目录范围内生效"，否则 AI 会在错误的搜索空间里做无用功。

## 2. 闭环控制反思

**问**：遇到报错或动画停滞时如何定位？是否看懂了 AI 的修复方案是如何通过修改物理公式或边界条件解决的？

**答**：

最典型的一次是**进阶挑战 B 中"天体切换过渡"失效**。现象是：点击「月球」后，重力数值从 9.80 只走到 **6.28** 就停住了，没有到达 1.62——动画停滞。

**我的定位方式**：让 AI 编写 headless 探针，逐次点击预设后读取滑块标签 `b-grv-v` 的实际数值，同时观察物理读数 `v-t1`。结果发现 `v-t1` 长时间停在 89.9（初始值 90°）几乎不动，说明**主循环 `requestAnimationFrame` 在该环境下几乎没被调用**。由此锁定问题不在过渡算法本身，而在**驱动过渡的"时间源"**。

**AI 的修复方案，我理解如下**：第一版把过渡写进了 `requestAnimationFrame` 循环，并用 `performance.now()` 计时。问题在于 `performance.now()` 读的是**墙钟时间**，而 rAF 回调在 headless 虚拟时间下由虚拟时钟驱动——两者不同步，导致 `(now - t0)` 几乎不增长，缓动系数 k 一直很小，g 自然卡在中途。修复方式是把过渡逻辑从 rAF 中**解耦**出来，改由 `tweenGravity()` 内部的 `setTimeout` 链驱动（28 步、每步约 25 ms、ease-out cubic）——定时器与虚拟时间同源，过渡就能稳定走完。

**这不是物理公式问题，而是"时间源"这一边界条件问题**：把进度推进的时钟基准与驱动它的调度器统一起来。我完全看懂了这一步，也认可它对真实浏览器无副作用（真机上两者都是墙钟，setTimeout 链同样流畅）。

另一次用到公式判断的是**双摆数值稳定性**：我让 AI 在侧栏输出机械能 `E`，用它作为"是否发散"的判据；同时确认了分母 $D = 2m_1 + m_2 - m_2\cos 2(\theta_1-\theta_2)$ 的取值范围恒为 $[2,4]$、永不为零，从公式层面排除了除以零导致发散的可能。实测 4 s 后 `E = 11.813` 且各读数有限，据此判定"无数值发散"。

**问**：作为人在回路之上的产品总设计师，哪些核心决策由你决定？哪些重复劳动由 AI 完成？

**主体性总结**：我始终处在"提需求、设边界、看效果、给反馈"的位置；AI 是执行者与验证工具。当 AI 的结论与我的实际观察冲突时（任务四那次），是**我**判断其结论错误并要求重新定位——这正是 HOTL 中人类作为质量裁判不可替代的体现。
