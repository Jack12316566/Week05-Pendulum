## 任务四排错记录

**`index_buggy_demo.html`** 源自课程提供的演练代码，原版缺陷如下：

- 报错：点击「重置摆动」后控制台抛出 `Uncaught ReferenceError: resetAnimation is not defined at HTMLButtonElement.onclick`
- 根因：按钮内联 `onclick="resetAnimation()"` 在全局作用域查无此标识符；脚本里同名函数实为 `resetSimulationState()`，名称不一致 → 错误只在点击触发时抛出
- 修复：
  1. 删除按钮的内联 `onclick` 属性
  2. 将函数统一重命名为 `resetAnimation()`
  3. 改用 `addEventListener('click', resetAnimation)` 在脚本作用域内绑定
- 验收：MS Edge headless 探针（自动 click + 错误监听 + 状态断言） → `PASS`，`errCount=0`，点击后 `angle = π/4` 精准复位

## 双摆升级记录

将正式版 `index.html` 由单摆升级为**双摆模拟器**，核心变更：

- **物理模型**：由单摆小角度近似改为双摆拉格朗日动力学，采用 **RK4 4 阶数值积分**，固定步长 `1/480 s`。
- **分母保证**：$D = 2m_1 + m_2 - m_2 \cos 2(\theta_1 - \theta_2) \in [2,4]$，永不为零，无数值发散。
- **彩虹渐变拖尾**：末端摆球 bob2 轨迹以 `hsla(simTime·40 + frac·360, 90%, 62%, frac·0.85)` 上色，色相随时间漂移，alpha 沿尾部衰减。
- **拖拽交互**：支持鼠标直接拖动任一摆球；拖 bob1 时通过逆运动学（IK）保持 bob2 屏幕位置不变，避免杆长视觉跳变。
- **验收**：Edge headless 探针 13 项断言全部 PASS；4 s 仿真后 t₁/t₂/ω₁/ω₂/E 全部有限；拖到目标角度误差 ≤ 1°。

## 选做：天体预设与数据持久化

在双摆基础上完成进阶选做：

- **4 个天体胶囊按钮**：地球（g=9.80）、月球（g=1.62）、木星（g=24.79）、太空（g=0.00）。

## 人机协同三反思

### 反思一：意图表达与需求澄清

本次实验最开始的任务是修复一个运行时 `ReferenceError`。用户最初只给出报错截图与“点击重置按钮报错”的描述，我首先通过静态搜索确认官方版本中并不存在该缺陷，进而发现真正的演练代码位于仓库根目录的另一份 `index.html`。这一经历让我意识到：在人机协同中，**意图的精确表达**与**上下文的完整传递**同样重要。AI 必须主动求证、缩小范围，而不是在错误文件上直接修改；用户也需要指出具体文件或提供堆栈，才能避免无效劳动。

### 反思二：代码生成与验证闭环

双摆升级涉及拉格朗日方程推导、RK4 积分、逆运动学拖拽以及 Headless 浏览器探针验收。AI 在生成代码时给出了可运行的实现，但代码正确性不能仅靠“看起来对”来保证。我养成了**每次修改后注入探针**的习惯：通过模拟点击、PointerEvent、读取 DOM 读数与 localStorage，累计 30 余项断言覆盖功能、数值稳定性与持久化。人机协同的闭环应当是“生成 → 验证 → 修正 → 再验证”，而不是一次性交付。

### 反思三：版本管理与实验留痕

本次实验严格使用 Git 进行归档：基线提交、排错修复、双摆升级、天体预设与持久化，每一步都有清晰的 commit message。Git 不仅是代码备份工具，更是**人机协同过程的反思载体**——通过 `git log --oneline` 可以清晰看到需求如何被逐步拆解、实现与验证。最终把选做任务的天体修改版与修改前版本拆分为两个程序并放入独立文件夹，也便于他人（或未来的自己）对比“修改前/后”的差异，完成实验记录的闭环。
